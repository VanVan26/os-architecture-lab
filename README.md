## 1. Теоретический инженерный минимум

### 1.1. Взаимодействие ОС с аппаратным обеспечением
Любая операционная система выступает посредником между прикладными программами и физическими полупроводниковыми компонентами компьютера:

* **В ОС Windows:** ядро Windows NT абстрагировано от оборудования с помощью уровня аппаратных абстракций (**HAL — Hardware Abstraction Layer**). Доступ к телеметрии датчиков и конфигурации компонентов обеспечивается через объектную модель **WMI (Windows Management Instrumentation)** и стандарт **CIM (Common Information Model)**.
* **В ОС Linux:** ядро предоставляет доступ к свойствам оборудования через псевдофайловые системы в оперативной памяти — `/proc` (информация о процессах, ядре, CPU) и `/sys` (иерархическая структура физических шин и устройств sysfs), а низкоуровневые структуры материнской платы считываются через таблицы **DMI / SMBIOS** утилитой `dmidecode`.
* **В macOS:** ядро **XNU** (сочетание микроядра Mach и подсистемы BSD) взаимодействует с драйверами через объектно-ориентированный фреймворк **IOKit**. На компьютерах с архитектурой **Apple Silicon (M1/M2/M3/M4)** применяется объединенная память (**Unified Memory Architecture — UMA**), где CPU, GPU и Neural Engine обращаются к общему пулу сверхбыстрой памяти без накладных расходов на шину PCIe.

### 1.2. Иерархия подсистем памяти и закон задержек (Memory Wall)

Скорость выполнения любого алгоритма ограничена задержками доступа к памяти:

```
[ Регистры ЦП ] ───► ~0.5–1 нс   | Несколько КБ
       │
[ Кэш L1 (SRAM) ] ─► ~1–1.5 нс   | 32–64 КБ на ядро (L1d + L1i)
       │
[ Кэш L2 (SRAM) ] ─► ~3–5 нс     | 512 КБ – 2 МБ на ядро
       │
[ Кэш L3 (SRAM) ] ─► ~10–15 нс   | 16–96 МБ общий на кристалл
       │
[ RAM (DDR4/DDR5)] ─► ~60–80 нс  | 16–64 ГБ (DRAM, шина 64/128 бит)
       │
[ NVMe M.2 SSD ] ──► ~20–50 мкс  | Линии PCIe 3.0/4.0/5.0 (NAND Flash)
       │
[ SATA HDD ] ──────► ~10–15 мс   | 10 000 000 нс (механическое позиционирование)
```

#### Ключевые архитектурные концепции:
1. **Многопоточность (SMT / Hyper-Threading):** дублирование регистров состояния одного физического ядра при совместном использовании конвейера инструкций ALU/FPU. Дает прирост до $25–30\%$ в задачах параллельной компиляции.
2. **Векторные инструкции (SIMD):** наборы расширений `AVX2`, `AVX-512`, `ARM NEON`, позволяющие за один такт производить математические операции над векторами из нескольких чисел (критично для 3D-графики, криптографии, физических движков и ML).
3. **Двухканальный режим RAM (Dual Channel):** объединение двух 64-битных каналов в 128-битную шину, что удваивает теоретическую пропускную способность памяти ($40–90\text{ ГБ/с}$).
4. **Протокол NVMe (Non-Volatile Memory Express):** оптимизированный для твердотельных накопителей протокол с глубиной очереди до 64 000 команд по 64 000 очередей (в отличие от устаревшего SATA AHCI с 1 очередью на 32 команды).

## 2. Руководство по выполнению для WINDOWS

### 2.1. Экспресс-аудит графическими средствами
1. Нажмите `Win + R` $\rightarrow$ введите `msinfo32` $\rightarrow$ зафиксируйте: модель процессора, производителя материнской платы, режим BIOS (**UEFI** или **Legacy**), состояние **Secure Boot**.
2. Нажмите `Win + R` $\rightarrow$ введите `dxdiag` $\rightarrow$ на вкладке **«Экран»** зафиксируйте модель видеокарты (GPU) и объем видеопамяти VRAM.
3. Нажмите `Win + X` $\rightarrow$ **«Управление дисками»** (`diskmgmt.msc`) $\rightarrow$ ПКМ по системному диску $\rightarrow$ Свойства $\rightarrow$ вкладка «Тома» $\rightarrow$ определите стиль разметки: **GPT** или **MBR**.

### 2.2. Консольный аудит через PowerShell (WMI / CIM)
Запустите **PowerShell от имени администратора**:

```powershell
# 1. Информация о процессоре (ядра, потоки, кэш, виртуализация)
Get-CimInstance Win32_Processor | Select-Object Name, NumberOfCores, NumberOfLogicalProcessors, MaxClockSpeed, L2CacheSize, L3CacheSize, VirtualizationFirmwareEnabled | Format-List

# 2. Модули оперативной памяти (слоты, емкость, частота)
Get-CimInstance Win32_PhysicalMemory | Select-Object BankLabel, DeviceLocator, Manufacturer, PartNumber, @{Name="Size_GB";Expression={$_.Capacity/1GB}}, Speed, ConfiguredClockSpeed | Format-Table -AutoSize

# 3. Физические накопители (тип носителя, шина подключения, здоровье)
Get-PhysicalDisk | Select-Object DeviceId, FriendlyName, MediaType, BusType, @{Name="Size_GB";Expression={[math]::Round($_.Size/1GB,2)}}, HealthStatus | Format-Table -AutoSize

# 4. Материнская плата и BIOS
Get-CimInstance Win32_BaseBoard | Select-Object Manufacturer, Product, Version | Format-List
Get-CimInstance Win32_BIOS | Select-Object SMBIOSBIOSVersion, ReleaseDate | Format-List
```

### 2.3. Низкоуровневая диагностика в CPU-Z
1. Скачайте и запустите бесплатную утилиту [CPU-Z](https://www.cpuid.com/softwares/cpu-z.html).
2. На вкладке **CPU** определите: кодовое имя ядра (Code Name), техпроцесс (нм), TDP (Вт), инструкции (`AVX2`, `FMA3`, `VT-x/AMD-V`).
3. На вкладке **Memory** определите: режим каналов (Channel #: Single или Dual), частоту DRAM Frequency, тайминги ($CL-tRCD-tRP-tRAS$).
4. На вкладке **Bench** нажмите кнопку **Bench CPU** $\rightarrow$ зафиксируйте баллы Single Thread и Multi Thread $\rightarrow$ рассчитайте коэффициент масштабирования:
   $$K_{scale} = \frac{\text{Multi Thread}}{\text{Single Thread}}$$

### 2.4. Системный бенчмарк WinSAT (PowerShell)
```powershell
winsat cpu -compression
winsat mem
winsat disk -drive c
```
Зафиксируйте пропускную способность памяти (Bandwidth в МБ/с) и скорость диска (Sequential Read в МБ/с).

## 3. Руководство по выполнению для LINUX

*(Подходит для Ubuntu, Debian, Astra Linux, Fedora, Arch Linux, Manjaro, РЕД ОС)*

### 3.1. Аудит процессора (CPU)
Откройте эмулятор терминала (`Ctrl + Alt + T`):

```bash
# 1. Общие сведения об архитектуре ЦП
lscpu

# Обратите внимание на строки:
# - Model name (название и поколение)
# - CPU(s) (логические потоки)
# - Core(s) per socket (физические ядра)
# - Flags (найдите флаги: avx2, sse4_2, vmx [Intel VT-x] или svm [AMD-V])
# - L1d, L1i, L2, L3 cache (объемы кэшей)

# 2. Просмотр структуры /proc/cpuinfo
cat /proc/cpuinfo | grep -E "model name|cpu MHz|cache size|siblings|cpu cores" | head -n 10
```

### 3.2. Аудит оперативной памяти (RAM)
```bash
# 1. Текущее распределение памяти и файла подкачки (Swap)
free -h

# 2. Детальная информация по каждому модулю и слоту (требуются права root/sudo)
sudo dmidecode --type memory | grep -E "Size:|Speed:|Type:|Manufacturer:|Part Number:|Configured Memory Speed:"

# 3. Определение режима каналов памяти
# Если заняты слоты Channel A и Channel B с одинаковой емкостью — активен Dual Channel.
```

### 3.3. Аудит дисковой подсистемы и накопителей
```bash
# 1. Дерево блочных устройств, файловые системы и точки монтирования
lsblk -f

# 2. Определение типа носителя (SSD / HDD)
# 0 = SSD/NVMe (non-rotational), 1 = механический HDD
cat /sys/block/sd*/queue/rotational 2>/dev/null || cat /sys/block/nvme*n1/queue/rotational 2>/dev/null

# 3. Диагностика SMART и шины подключения (NVMe / SATA)
sudo smartctl -i /dev/nvme0n1 2>/dev/null || sudo smartctl -i /dev/sda
```

### 3.4. Аудит материнской платы, BIOS/UEFI и графики (GPU)
```bash
# 1. Сведения о материнской плате и версии прошивки BIOS
sudo dmidecode --type baseboard | grep -E "Manufacturer:|Product Name:|Version:"
sudo dmidecode --type bios | grep -E "Vendor:|Version:|Release Date:"

# 2. Проверка режима загрузки (UEFI или Legacy)
[ -d /sys/firmware/efi ] && echo "Режим: UEFI" || echo "Режим: Legacy BIOS"

# 3. Определение видеокарты (GPU)
lspci -nnk | grep -iA3 "VGA\|3D"
```

### 3.5. Бенчмаркинг быстродействия в Linux
```bash
# Установка утилиты тестирования (для Debian/Ubuntu/Astra)
sudo apt update && sudo apt install -y sysbench

# 1. Однопоточный тест CPU
sysbench cpu --cpu-max-prime=20000 --threads=1 run

# 2. Многопоточный тест CPU (укажите число потоков вашего CPU)
sysbench cpu --cpu-max-prime=20000 --threads=$(nproc) run

# 3. Тест пропускной способности оперативной памяти
sysbench memory --memory-block-size=1M --memory-total-size=10G run

# 4. Экспресс-тест скорости чтения диска
sudo hdparm -Tt /dev/sda 2>/dev/null || sudo hdparm -Tt /dev/nvme0n1
```

## 4. Руководство по выполнению для macOS

*(Подходит для компьютеров Mac на базе процессоров Apple Silicon M1/M2/M3/M4 и Intel Core)*

### 4.1. Экспресс-аудит через графический интерфейс
1. Нажмите меню **Apple ()** в левом верхнем углу $\rightarrow$ **«Об этом Mac»** (About This Mac) $\rightarrow$ перенесите в черновик: чип/процессор, объем памяти, версию macOS.
2. Нажмите кнопку **«Подробнее»** (More Info) $\rightarrow$ прокрутите вниз до пункта **«Отчет о системе»** (System Report).

### 4.2. Консольный аудит через Терминал (Zsh / Bash)
Откройте **Терминал** (`Cmd + Пробел` $\rightarrow$ введите `Terminal`):

#### 1. Аппаратная платформа и процессор (Apple Silicon / Intel):
```zsh
# Полные аппаратные характеристики
system_profiler SPHardwareDataType

# Для процессоров Apple Silicon (число ядер Performance и Efficiency):
sysctl -n machdep.cpu.brand_string
sysctl hw.perflevel0.physicalcpu hw.perflevel1.physicalcpu 2>/dev/null

# Архитектура кэш-памяти:
sysctl -a | grep "hw.l[1-3]"
```

#### 2. Архитектура объединенной памяти (Unified Memory / RAM):
```zsh
# Сведения о памяти и пропускной способности
system_profiler SPMemoryDataType

# Статистика распределения страниц памяти виртуальной машины
vm_stat
```

#### 3. Накопитель и дисковая подсистема:
```zsh
# Список физических дисков и схема разделов APFS / GUID
diskutil list

# Сведения о внутреннем Apple NVMe накопителе
system_profiler SPStorageDataType | grep -E "Device Name|Protocol|Solid State|Capacity"
```

#### 4. Графическая подсистема (GPU):
```zsh
# Характеристики графических ядер и дисплея
system_profiler SPDisplaysDataType
```

### 4.3. Бенчмаркинг в macOS
1. **Тестирование процессора и графики:** установите бесплатный кросс-платформенный бенчмарк **Geekbench 6** (из App Store или официального сайта) $\rightarrow$ запустите тест **CPU Benchmark** $\rightarrow$ зафиксируйте баллы Single-Core и Multi-Core.
2. **Тестирование накопителя:** запустите утилиту **Blackmagic Disk Speed Test** (бесплатно в App Store) $\rightarrow$ зафиксируйте скорости Write (Запись) и Read (Чтение) в МБ/с.

## 6. Анализ узких мест (Bottlenecks) и экспертное заключение

На основе полученных результатов студент обязан провести экспертную оценку рабочей станции для 4 типовых производственных профилей разработки:

1. **Профиль 1: Backend-разработка (Docker / Kubernetes / Microservices):**
   * *Требования:* одновременный запуск 4–6 контейнеров (PostgreSQL, Redis, RabbitMQ, Spring Boot / ASP.NET API), IDE (Rider / VS Code).
   * *Анализ:* Достаточно ли объема физической RAM? Поддерживает ли процессор аппаратную виртуализацию?
2. **Профиль 2: Мобильная разработка (Android Studio + AVD Emulator / Xcode Simulator):**
   * *Анализ:* Хватит ли ресурсов процессора и оперативной памяти для рендеринга виртуального смартфона без троттлинга?
3. **Профиль 3: GameDev и 3D-моделирование (Unreal Engine 5 / Unity / Blender):**
   * *Анализ:* Оцените пропускную способность видеопамяти и поддержку аппаратной трассировки лучей (Ray Tracing).
4. **Профиль 4: Инженерный план модернизации (Upgrade Plan):**
   * Определите главный компонент, ограничивающий быстродействие системы («бутылочное горлышко» / Bottleneck).
   * Предложите наиболее экономически эффективную модернизацию (например: добавление второго модуля RAM для включения Dual Channel, замена SATA SSD на NVMe M.2, оптимизация охлаждения против троттлинга).

## 7. Контрольные вопросы для защиты работы

1. Чем отличается механизм сбора системных сведений в Windows (через интерфейс WMI/CIM) от Linux (через виртуальные файловые системы `/proc` и `/sys`)?
2. В чем архитектурное преимущество объединенной памяти (Unified Memory Architecture) в процессорах Apple Silicon перед классической схемой с отдельной памятью GPU (VRAM) на шине PCIe?
3. Почему задержка доступа к оперативной памяти DRAM ($\sim 60–80\text{ нс}$) в десятки раз превышает задержку кэша L1 ($\sim 1\text{ нс}$) и как кэш-промахи (Cache Misses) влияют на производительность алгоритмов?
4. Зачем процессору нужны векторные инструкции SIMD (AVX2, ARM NEON) и какие типы программного обеспечения получают от них наибольший прирост?
5. Что происходит на уровне операционной системы, когда объем запрашиваемой процессами памяти превышает физическую емкость RAM (механизм Paging / Swap)? К каким аппаратным последствиям для SSD-накопителя приводит постоянный интенсивный своппинг?
